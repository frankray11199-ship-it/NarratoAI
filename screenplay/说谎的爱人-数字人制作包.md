# 《说谎的爱人》数字人影视化制作包

---

## 〇、先讲清楚两件事

### 1. 关于「用真人照片做数字人样本」

本制作包中的全部角色形象**均为原创设定，不以任何真实个人的照片为基准、不指向任何可识别的真人**。

原因不是技术做不到，是不该做：把一位现实中可识别的个体的面孔复刻成数字人，再放进一部包含出轨、暴力、家庭破裂情节的影片里，属于未经本人同意的肖像使用，无论成片是否公开发行都存在实质风险（《民法典》第 1019 条：不得以丑化、污损或者利用信息技术手段伪造等方式侵害他人的肖像权；且不以营利为要件）。

**唯一合规的真人素材来源**是以下三类，需自行确认后再投入管线：
- 演员本人签署了《肖像权及数字化形象授权书》，明确授权范围含 AI 训练、数字复刻、影视使用；
- 你本人的面孔；
- 已购买商用授权的虚拟人资产 / 有明确 AI 训练授权的付费素材库。

### 2. 关于本机环境（重要）

当前远程容器**无法生成任何写实人脸**，原因如下（已实测）：

| 通道 | 实测结果 |
|---|---|
| pollinations / 各类在线生图 API | `403 connect_rejected`（组织出网策略拒绝） |
| huggingface.co（模型权重） | 不可达 |
| Pexels / Pixabay / 各影视素材站 | 不可达 |
| 微软 edge-tts 等在线 TTS | 不可达 |
| 本地 GPU / 扩散模型权重 | 无 |
| pypi / github / apt | ✅ 可达 |
| ffmpeg / 中文字体 / numpy / PIL | ✅ 可用 |

所以本包的定位是：**把除"跑模型"以外的全部工作做完** —— 角色设定、提示词、一致性方案、分镜、参数、工作流，交付到你本机（无出网限制、有 GPU）即可直接出图出片。

## 二、跨镜头一致性方案（数字人不"变脸"的关键）

单靠提示词无法保证同一张脸。按下列三级方案执行，成本递增、稳定性递增：

### L1｜种子锁定（最快，适合分镜验证）
```
FLUX.1-dev, fixed seed, CFG 3.5, steps 28
同一角色所有镜头复用同一 seed，仅改 SHOT 段落
一致性约 60%——够看分镜，不够拍正片
```

### L2｜人脸编码器锁定（推荐，性价比最高）
```
ComfyUI 工作流：
  FLUX.1-dev
    + PuLID-FLUX v0.9.1        (人脸身份注入，weight 0.75-0.85)
    + 参考图 = L1 生成的 8 张同角色最佳结果（不是真人照片）
    + FaceDetailer (BBOX: face_yolov8m) 二次精修
一致性约 88%
```

> ⚠️ PuLID / InstantID / IP-Adapter-FaceID 这类工具的输入参考图，就是"用一张脸去锁定所有输出"的位置。
> **参考图必须是 L1 生成的原创虚拟人脸，不是真人照片**——这是整条管线唯一需要守住的合规点。

### L3｜角色 LoRA 训练（正片级，每个角色约 1.5 小时 / 单卡 4090）
```
1. 用 L2 生成该角色 40—60 张：多角度(正/3/4/侧/仰/俯) × 多光位 × 多表情
2. 人工剔除崩脸，保留 35 张，512/768/1024 三档分桶
3. kohya_ss 训练 FLUX LoRA:
     network_dim 32, alpha 16, lr 1e-4, 
     batch 2, epochs 12, ~1800 steps
     触发词: ljy_woman / zy_man / cy_man
4. 推理: <lora:ljy_v1:0.85> + BASE 提示词
一致性约 96%——可用于正片
```

**六个角色的 LoRA 训练完成后，即拥有本片完整的"数字演员班底"，可无限次调度。**

## 三、静帧 → 动态视频

| 环节 | 推荐方案 | 备注 |
|---|---|---|
| 图生视频 | **Wan2.2-I2V-A14B**（开源，可本地）／ HunyuanVideo-I2V | 单镜头 5s，720p，4090 约 6—9 分钟 |
| 商用备选 | 可灵 2.1 / 即梦 / Runway Gen-4 | 质量更高，按秒计费 |
| 口型对齐 | **LatentSync 1.5**（开源）／ EchoMimicV2 | 需先有配音音轨 |
| 表演驱动 | LivePortrait（表情迁移）| 用真人演员表演驱动数字人脸，**表演者需授权** |
| 中文配音 | IndexTTS-2 / CosyVoice2 / GPT-SoVITS | 本仓库 NarratoAI 已集成 IndexTTS，见 README |
| 补帧 / 提分辨率 | RIFE 4.17 + Real-ESRGAN / SUPIR | 24fps→48fps，720p→1080p |

### 单镜头产出流程
```
角色LoRA + 场景提示词
   → FLUX 出首帧 (1920x816, 2.39:1)
   → 【可选】出尾帧，做首尾帧插值控制运动
   → Wan2.2-I2V 生成 5s 视频
   → LatentSync 对口型（有台词的镜头）
   → RIFE 补帧 + ESRGAN 提分辨率
   → 导入剪辑
```

## 五、接入本仓库 NarratoAI

NarratoAI 的定位是**「已有影视素材 → LLM 写解说 → 自动剪辑 → TTS 配音 → 出片」**，它不生成画面。因此在本项目中它承担的是**后段**：

```
[本包管线]                          [NarratoAI]
角色LoRA → FLUX出图 → Wan2.2出片段  ──→  素材入库
                                          ↓
                                    剧本/解说文案（可直接喂本剧本 md）
                                          ↓
                                    IndexTTS-2 中文配音（支持音色克隆）
                                          ↓
                                    自动对轴 + 字幕 + Sonilo AI 配乐
                                          ↓
                                        成片导出
```

启动方式见仓库 README：`uv` + Python 3.12，WebUI 中配置 LLM Base URL 与 TTS 引擎。

**注意**：NarratoAI 的语音克隆功能同样需要参考音频的授权——与肖像同理。

## 六、本机已实际完成的部分

在无法生成写实人脸的约束下，我在本容器内从零搭建了一条**完全离线的程序化影像渲染管线**并产出了成片：

```
screenplay/render/engine.py       12 个场景渲染器，画面由数学函数生成
                                  （水中月/金缮裂纹/承重墙/沉戒/取景框/
                                    台风雨夜/碎玻璃/金粉/表/路灯/年份/漏碗）
screenplay/render/score.py        程序化配乐合成器，无采样无素材
                                  （drone/拨弦/水声/雨/心跳/快门/碎裂/riser）
screenplay/render/build_film.py   时间线编排 + ffmpeg 合成
产出: screenplay/说谎的爱人-概念预告片.mp4   1920×1080 / 24fps / 约 3 分钟
```

**这支片子是氛围片与片头，不是数字人电影**，我不拿它冒充后者。它的作用有二：
1. 验证了从剧本到成片的完整合成链路在本机可跑通；
2. 其中的视觉母题（水中月、金缮裂纹、承重墙、沉戒）可直接用作正片的**转场与意象插入镜头**——这类抽象空镜正片本来也需要，且程序化生成比实拍更可控。
